REAL CAMERA -> RING FEATURES -> SAVED POLICY: MOTORS-OFF PREVIEW

1. On normal internet, extract and run 1-Setup.command.
2. At the lab, power the drone with motors OFF and join Tello Wi-Fi.
3. Close other drone programs, including the recorder. Run 2-Camera-Policy.command.
4. Allow Local Network access if macOS asks. Q quits, R resets history.
5. Inspect the green fitted ellipse and blue mask. Move the drone by hand.
   The four numbers are proposed actions, NOT commands sent to the drone.
6. Send the sessions folder with your camera recordings and measurements.

This package provides a real camera/policy connection. Physical movement is
disabled: no takeoff, rc, landing or movement command exists in its send allowlist.
It is not a completed autonomous flight controller. The current policy has not
passed a real flight test. It is NOT safe to turn its suggestions into RC values
by simply multiplying by100: simulated speed and real RC response must be measured.

Required before a flight-enabled version:
- Measured camera intrinsics/distortion at actual stream resolution (the bundled
  920px focal lengths are explicitly provisional, NOT measured calibration).
- Validation of blue-ring segmentation in the lab. Other blue objects, hanger
  straps and partial arcs may create incorrect ellipse fits.
- Confirm a visible front-only marker and configure its colour. Marker defaults
  to absent; we never label the ring front-facing just because it is visible.
- Real speed/yaw command mapping, response delay, and manual takeover/link-loss
  testing with the established lab controller. Available telemetry remains to verify.

The bridge uses the exact trained119D memory contract and preserves its nominal
ring estimator. With no issued movement it logs zero command history; it does
NOT pretend its proposed actions moved the drone. Hand movement means nominal
command odometry is inaccurate, so preview output is diagnostic, not flight evidence.
There is no true position, wall distance or simulated pose in camera observations.
Stale frames pause predictions; long timing gaps reset histories. These are
preview behaviours, not a certified flight-loss response.

Saved video can also be checked without drone Wi-Fi from Terminal:
  .venv/bin/python camera_policy.py --video /path/to/camera.h264
Fallback when double-click is blocked: bash 1-Setup.command / bash 2-Camera-Policy.command
Mac dependencies and actual hardware are unverified until setup/lab checks pass.
