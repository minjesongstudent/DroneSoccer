1. On normal internet, run 1-Setup.command. It installs requirements and runs
   offline tests, including the actual PC model through a mocked command sink.
2. Run 5-Check-Control-Timing.command on the Mac. It measures this actual model,
   with no drone connection. This is a necessary check, not flight validation.
3. For a physical test, use the enclosed cage, fitted guards and a supervising
   operator. Close other drone controllers. Join the Tello Wi-Fi locally.
4. Run 2-Supervised-Flight.command and type FLIGHT. This opens the local UI.
   It does NOT take off until you check the supervision box and click once.
5. Verify the UI says full_horizon-round-05 and the correction hash starts
   eba7030c and Vertical search v2. Click Take off + find ring + run policy once.
   This sends REAL takeoff, scripted acquisition RC, then learned policy RC.
   Keep the UI focused. LAND NOW or Escape requests landing. There is no fixed
   ten-second policy limit. Loss of fresh camera/telemetry/UI/inference, height,
   battery and temperature checks request landing. No automatic restart.

After takeoff, the drone settles, then can rise slowly toward measured 120 cm
and turn in place clockwise/counterclockwise to find the ring. No forward or
sideways search. The 150 cm ceiling remains. Ascent is limited to five seconds;
each turn leg to three seconds. If still unseen, lower toward 80 cm for up to
five seconds while looking. The complete search is capped at 20 seconds.
Forward/backward and sideways RC remain ZERO throughout search. This is not
guaranteed physical XY position hold: drift can still occur.
The ring must remain detected for at least three fresh frames across 0.4 seconds
while neutral RC is requested, then the learned policy takes over. No ring,
bad/stale inputs or a stop condition requests landing. No automatic retry.
These are bounds, not a guarantee of actual physical altitude/turn response.
Detection is not a guarantee of correct target identification. The learned loop
can legitimately lose the ring later; this startup routine is not learned recovery.

Startup search RC is SCRIPTED and logged separately in startup_search.jsonl.
After handoff, navigation RC is the learned model's output with team scaling
50/50/100/70 and integer quantization. Camera and actual issued action history
remain continuous across the handoff. Takeoff/landing are SDK actions. Telemetry
is used for recording and stop checks, not invented actor observations.
An emergency motor cut is separate and drops the drone. UDP sends/landing
requests do not confirm delivery or motor state; observe the physical outcome.

Each session saves camera.h264, telemetry.jsonl, commands.jsonl, policy events,
89-input observations, raw outputs, actually issued quantized actions and
timestamps. Every policy row/metadata includes all model component identities.
The UI clearly distinguishes STARTUP SEARCH from LEARNED POLICY CONTROL.
comparison.csv joins commands to preceding telemetry; it is not a measured
global 3D trajectory or automatic proof of a ring passage. Export is automatic;
3-Export-Latest.command can export the latest folder again without deleting it.

2-Motors-Off-Record.command is explicitly a different, non-flight mode.
4-Replay-Latest.command runs policy suggestions on recorded video, no motors.
No physical flight was performed or validated while building this package.
